## 1. Voice Postgres backup **[unverified offline]**

```bash
cd "$VOICE_LINK"
# 1a. The 1.49.0 schema head; expect b3c1d9e4f7a2.
railway ssh --service dograh-api -- sh -c 'cd /app && alembic -c api/alembic.ini current'
# 1b. Logical dump to this Mac. pg_dump runs in the database container over its local socket (no password handled here);
#     base64 keeps the custom-format dump byte-exact through the SSH stream.
DUMP="$DUMP_DIR/dograh-pre-151-$(date -u +%Y%m%dT%H%M%SZ).dump"
railway ssh --service "$PG_SERVICE" -- sh -c 'pg_dump -U "${POSTGRES_USER:-postgres}" -d "${POSTGRES_DB:-postgres}" -Fc | base64' | tr -d '\r' | base64 -d > "$DUMP"; chmod 600 "$DUMP"; ls -l "$DUMP"
# 1c. Proof the file is a complete dump: lists the tables Dograh needs, from a clean postgres:17 client.
docker run --rm -v "$DUMP_DIR:/b:ro" postgres:17 pg_restore -l "/b/$(basename "$DUMP")" | grep -cE 'TABLE public (alembic_version|tools|workflows|workflow_runs|workflow_definitions) '   # expect 5
```

If 1b fails or 1c does not print 5, stop. Alternative for 1b: `railway connect "$PG_SERVICE" --tunnel-only -P 55432` in a second terminal, then
`docker run --rm -e PGPASSWORD -v "$DUMP_DIR:/b" postgres:17 pg_dump -h host.docker.internal -p 55432 -U <user> -d <db> -Fc -f "/b/$(basename "$DUMP")"`
after `IFS= read -rs PGPASSWORD; export PGPASSWORD`. If the Postgres service shows a Backups tab in the Railway dashboard, also take a volume backup there.

## 8. Three test calls **[unverified offline]**

Use a phone whose number is saved, with a real name, as a contact of the workspace that owns `$TO_NUMBER_KO`, with one open Task and a
project with an estimate.

1. **Known caller.** Call `$TO_NUMBER_KO`, say `지난번에 견적 문의했던 건으로 전화드렸어요`. Hear today's greeting with the business name, then a
   reply that asks whether you are that contact (`○○님 맞으세요?`) instead of asking your name. Dograh → Agent Runs → the run → Context shows
   `caller_name` and `caller_history`.
2. **Lookup.** Call again, say `견적 어떻게 됐어요?`, confirm the name. Hear `확인해 보겠습니다.` (and `잠시만 기다려 주세요.` only if the lookup takes over
   2.5 s), then one sentence with what the record says (e.g. the estimate was sent), no price, no date promise, and the owner will follow up. The run
   shows a `lookup_caller_work_ko` tool call with HTTP 200.
3. **Outcome label.** After hanging up, wait about a minute (the outcome is classified after the hangup). Synchronize's 전화 tab shows the call's
   label from the eight outcomes (call 2 should read as a message about existing work), and the Dograh run's `call_disposition` is that code.
   A call still showing `user_hangup` after five minutes means the post-call classifier failed: read the dograh-api log.

## R. Rollback (newest change first) **[unverified offline]**

```bash
# R1. Workflows: each apply's printed ROLLBACK FILE, English then Korean. Restores definition, settings and a backed-up tool definition.
WORKFLOW_ID=3 LANGUAGE=en; golive --rollback "$BACKUP_FILE_EN"
WORKFLOW_ID=1 LANGUAGE=ko; golive --rollback "$BACKUP_FILE_KO"
# R2. Only before an image rollback: Dograh's downgrade refuses tools with a delayed message. Keep only the start message
#     (or remove the delayed entry in Tools → lookup_caller_work_* → Save).
python3 -c 'import sys; sys.path.insert(0, sys.argv[1]); import golive
c = golive.Dograh()
for t in c.api("GET", "/tools/"):
    if t["name"].startswith("lookup_caller_work_"):
        d = t["definition"]; d["messages"] = [m for m in d["messages"] if m["event"] == "start"][:1]
        c.api("PUT", "/tools/" + t["tool_uuid"], {"definition": d}); print("cut", t["name"])' "$FORK/synchronize/workflows"
# R3. Schema back to 1.49.0's head, from the running 1.51.0 api (it knows both revisions).
railway ssh --service dograh-api -- sh -c 'cd /app && alembic -c api/alembic.ini downgrade b3c1d9e4f7a2 && alembic -c api/alembic.ini current'   # expect b3c1d9e4f7a2
# R4. Images back, api first.
railway service source connect --image dograhai/dograh-api:1.49.0 --service dograh-api --environment production
railway service status --service dograh-api --environment production   # until SUCCESS
curl -fsS --max-time 20 "$DOGRAH_PROOF_BASE_URL/api/v1/health" && echo " api healthy"
railway service source connect --image dograhai/dograh-ui:1.49.0 --service dograh-ui --environment production
# R5. Only if R3 failed: restore the step-1 dump. Every call after the backup is lost. Stop the api first so nothing writes.
railway down --service dograh-api --environment production --yes
railway connect "$PG_SERVICE" --tunnel-only -P 55432          # second terminal; leave it open
IFS= read -rs PGPASSWORD; export PGPASSWORD; printf '\n'
docker run --rm -e PGPASSWORD -v "$DUMP_DIR:/b:ro" postgres:17 pg_restore -h host.docker.internal -p 55432 -U <user> -d <db> --clean --if-exists --no-owner "/b/$(basename "$DUMP")"
railway service source connect --image dograhai/dograh-api:1.49.0 --service dograh-api --environment production
railway service redeploy --service dograh-api --environment production --from-source --yes
unset PGPASSWORD
```

After R1 the lookup tools stay in the organization unreferenced, like the credential; after R4 the End Call goodbyes are back in the 1.49 fields
(the downgrade converts one start message back).
