# Runbook 2026-11-08: Dograh 1.51.0, caller memory, record lookup, call outcomes

The owner runs this in a terminal (not the `!` box: several steps are interactive). Nothing here was run by the agent that wrote it;
every step marked **[unverified offline]** depends on the live Railway project, Dograh or Synchronize and could not be checked
without them. Secrets are typed only at silent reads (`IFS= read -rs`), never as arguments, and are unset at the end. What changed
and why: `UPGRADE-1.51.md` and `workflows/README.md` (Caller memory, Live wiring, Evals). A line that says `STOP` means stop there;
a line that says `go to R` means stop and roll back from the "Where to enter" table in R.

Order that matters:

- Steps 1–4 (Dograh 1.51.0) do not depend on Synchronize and can run first. Run steps 2–3 when no call is expected: if Railway keeps
  the 1.49 api serving while the new one migrates, an English call in that minute ends without its spoken goodbye (`UPGRADE-1.51.md`,
  Behaviour callers notice; not verifiable offline).
- Step 5 (go-live) needs the Synchronize release with the caller-work route and the pre-call caller fields (branch
  `fm/261108_voice_caller_context`) deployed and healthy: the probe refuses to continue without `/api/voice/tools/caller-work`.
- Step 5 needs this branch committed and the fork's tree clean (`golive.py` reads the templates from `HEAD`).
- Step 6 (evals) needs only step 5. Step 7 routes the Korean number only after step 6's results are read, so the first real call reaches
  the wired workflow and nobody hears the new Korean prompts before they were measured.

## 1. Voice Postgres backup **[unverified offline]**

```bash
cd "$VOICE_LINK"
# 1a. The 1.49.0 schema head; expect b3c1d9e4f7a2.
railway ssh --service dograh-api -- sh -c 'cd /app && alembic -c api/alembic.ini current'
# 1b. The database user and name inside the Postgres container (the dump below and R5 use the same).
read -r PG_USER PG_DB <<< "$(railway ssh --service "$PG_SERVICE" -- sh -c 'printf "%s %s\n" "${POSTGRES_USER:-postgres}" "${POSTGRES_DB:-postgres}"' | tr -d '\r')"; echo "db user $PG_USER, db $PG_DB"
# 1c. Logical dump to this Mac. pg_dump runs in the database container over its local socket (no password handled here);
#     base64 keeps the custom-format dump byte-exact through the SSH stream; pipefail reports a local break in the stream.
DUMP="$DUMP_DIR/dograh-pre-151-$(date -u +%Y%m%dT%H%M%SZ).dump"
( set -o pipefail; railway ssh --service "$PG_SERVICE" -- sh -c 'pg_dump -U "${POSTGRES_USER:-postgres}" -d "${POSTGRES_DB:-postgres}" -Fc | base64' | tr -d '\r' | base64 -d > "$DUMP" ) && chmod 600 "$DUMP" && ls -l "$DUMP" || echo 'STOP: the dump stream failed'
# 1d. Proof the dump is complete: pg_restore reads every data block to the end, so a stream cut anywhere
#     (including a pg_dump that failed inside the container) fails here.
docker run --rm -v "$DUMP_DIR:/b:ro" postgres:17 pg_restore -f /dev/null "/b/$(basename "$DUMP")" && echo "dump reads end to end" || echo 'STOP: the dump is incomplete'
# 1e. Extra check: the tables Dograh needs are in it.
docker run --rm -v "$DUMP_DIR:/b:ro" postgres:17 pg_restore -l "/b/$(basename "$DUMP")" | grep -cE 'TABLE public (alembic_version|tools|workflows|workflow_runs|workflow_definitions) '   # expect 5
echo "DUMP='$DUMP' PG_USER='$PG_USER' PG_DB='$PG_DB'"   # write this line down: R5 and a new terminal need it
schema_version   # expect b3c1d9e4f7a2 (the same as 1a, read from Postgres; R uses this when the api does not run)
```

If 1c or 1d printed `STOP`, or 1e does not print 5, stop (nothing has changed; no rollback). Alternative for 1c: `railway connect "$PG_SERVICE" --tunnel-only -P 55432` in a second
terminal, then `IFS= read -rs PGPASSWORD; export PGPASSWORD` and
`docker run --rm -e PGPASSWORD -v "$DUMP_DIR:/b" postgres:17 pg_dump -h host.docker.internal -p 55432 -U "$PG_USER" -d "$PG_DB" -Fc -f "/b/$(basename "$DUMP")"`,

## 8. Test calls **[unverified offline]**

For calls 1–3 use a phone whose number is saved, with a real name, as a contact of the workspace that owns `$TO_NUMBER_KO`, with one open
Task and a project with an estimate.

1. **Known caller, open matter.** Call `$TO_NUMBER_KO` and say only `여쭤볼 게 있어서 전화드렸어요`. Hear today's greeting with the business name,
   then a reply that asks whether you are that contact (`○○님 맞으세요?`) instead of asking your name, with nothing from your record yet. Say
   `네`. Hear one sentence that names your open matter (the open Task or estimate) and asks whether you are calling about it, with no date,
   price or progress promise. Dograh → Agent Runs → the run → Context shows `caller_name` and `caller_history`; after the call its gathered
   `customer_name` is the contact's name, and Synchronize's 전화 tab lists the call under that name, not the number.
2. **Lookup.** Call again, say `견적 어떻게 됐어요?`, confirm the name. Hear `확인해 보겠습니다.` (and `잠시만 기다려 주세요.` only if the lookup takes over
   2.5 s), then one sentence with what the record shows (e.g. the estimate was sent), no price, no date promise, and the owner will follow up. The run
   shows a `lookup_caller_work_ko` tool call with HTTP 200. Compare what you heard with the record in Synchronize: Call QA cannot (its transcript
   shows that the lookup ran, not what it returned), so this call is the only check that a relayed record is faithful.
   **Unconfirmed variant.** Call once more from the same phone, say `견적 어떻게 됐어요?`, and answer the name question with
   `아니요, 가족인데 이름은 괜찮아요`. Hear nothing from the record (no estimate, task or visit), only that the owner will check. Only the Persona
   prompt keeps the record from a caller who did not confirm the name (`workflows/README.md`, Caller memory); this is its only check.
3. **Outcome label.** After hanging up, wait about a minute (the outcome is classified after the hangup). Synchronize's 전화 tab shows the call's
   label from the eight outcomes (call 2 should read as a message about existing work), and the Dograh run's `call_disposition` is that code.
   A call still showing `user_hangup` after five minutes means the post-call classifier failed: read the dograh-api log.
4. **English line.** Call `$TO_NUMBER_EN`, give a reason and a name, and follow the call to the goodbye. Hear the greeting with the business
   name; after about a minute the 전화 tab shows the call with a label from the eight outcomes. This call decides whether R1 rolls back English.
